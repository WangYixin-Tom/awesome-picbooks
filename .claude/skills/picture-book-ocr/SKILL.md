# Picture Book OCR

帮助用户把一组绘本图片整理成两份文字：

1. 原始绘本故事文字。
2. 插入自然翻页提示语后的朗读/讲述版本。

## 适用场景

使用本 skill 处理以下请求：

- 用户提供一个绘本图片文件夹，希望按图片拍摄时间、修改时间或文件名排序。
- 用户希望从绘本图片中依次提取文字，整理成完整故事。
- 用户希望生成一个带翻页提示的版本，例如在每页之间加入“请翻到下一页”。
- 用户希望把结果保存到仓库中的故事文本目录。
- 用户只给出绘本名，例如“绘本我爱幼儿园帮我生成文字”，需要从 `images/` 下推断对应图片目录。

## 默认仓库结构

如果当前项目已经有这些目录，优先使用：

```text
images/                         # 绘本图片
stories/plain/                  # 原始绘本故事文字
stories/with-page-turns/        # 带翻页提示的绘本故事文字
```

如果目录不存在，先询问用户是否要创建；不要擅自改变已有项目结构。

## 工具使用原则

- 对 3 个以上步骤的任务，先用 `TaskCreate`/`TaskUpdate` 跟踪进度：定位目录、OCR、生成原文、生成翻页版、校验。
- 已知文件路径时用 `Read`/`Write`/`Edit`；列目录、排序、计数、校验时用 `Bash`。
- 读取图片或普通 Markdown/TXT 文件时，`Read` 不要传空的 `pages` 参数；`pages` 只用于 PDF，并且必须是 `"1"`、`"1-5"` 这类有效页码。
- **优先复用 skill 内置脚本，不要每次重写 OCR/处理脚本**：
  - `scripts/vision_ocr.swift`：macOS Vision OCR（自动尝试旋转方向）。
  - `scripts/run_ocr_pipeline.py`：图片排序 + OCR + 生成 `plain` 与 `with-page-turns` 两份输出。
- 默认先跑 `run_ocr_pipeline.py`；只有在脚本不可用、运行失败或结果明显异常时，才回退到多个只读 `Agent` 并行分批 OCR。
- 如果某个 OCR agent 被中断或失败，不要重做全部页面；只补齐缺失页段，再统一汇总。
- 如果系统进入 plan mode，除计划文件外不要写任何文件；先写简短执行计划并 `ExitPlanMode`，用户批准后再生成故事文本。

## 工作流

### 1. 确认输入

先确认或推断以下信息：

- 图片所在文件夹。
  - 用户明确给出路径时使用该路径。
  - 用户只给绘本名时，先列出 `images/` 下目录，寻找同名或最接近的文件夹。
- 排序方式：
  - 用户明确说按时间：优先使用图片 EXIF 拍摄时间；没有 EXIF 时使用文件修改时间。
  - 用户明确说按名字：按文件名自然排序，例如 `1.jpg, 2.jpg, 10.jpg`。
  - 用户没有说明：优先按文件名自然排序，因为绘本页码通常体现在文件名里；同时告诉用户这一点。
- 输出故事名称，例如 `小熊的一天`。如果用户没给名字，可根据图片文件夹名生成文件名。
- 输出文件名语言：和绘本故事语言保持一致；中文绘本优先使用中文文件名，英文绘本优先使用英文文件名。只替换操作系统不适合的字符，不要把中文标题默认转成拼音。
- 翻页提示语。默认使用：`请翻到下一页。`

### 2. 列出并排序图片

只处理常见图片格式：

```text
.jpg .jpeg .png .webp .heic .tif .tiff
```

推荐命令模式：

```bash
find images -maxdepth 2 -type d | sort
find 'images/<绘本名>' -maxdepth 1 -type f \( -iname '*.jpg' -o -iname '*.jpeg' -o -iname '*.png' -o -iname '*.webp' -o -iname '*.heic' -o -iname '*.tif' -o -iname '*.tiff' \) -print | sort -V
ls stories stories/plain stories/with-page-turns
```

注意：路径包含中文或空格时必须加引号。

排序后向用户简短说明：

- 找到多少张图片。
- 使用了哪种排序方式。
- 第一张和最后一张图片名。

如果看起来排序异常，例如文件名没有页码、时间完全一致、明显缺页，先提醒用户确认，不要继续生成错误故事。

### 3. OCR 提取文字

逐页读取图片并提取文字。每页保留页序信息，方便回溯：

```text
第 1 页
[这一页识别出的文字]

第 2 页
[这一页识别出的文字]
```

大批量图片建议并行分批 OCR，agent 提示应包含这些要求：

```text
Work read-only and do not modify files.
Read these image files in order and extract only the visible story text.
Preserve page order.
Fix obvious OCR line breaks/spaces, but do not invent missing text.
If a page has no text, write [本页无文字].
If unclear, mark [本页部分文字不清晰].
Return exactly this format for each page: 第 N 页\n<text>\n\n
```

整理 OCR 时：

- 修正常见识别错误、断行和多余空格。
- 保留绘本原本的语气和句子顺序，不主动改写故事。
- 不要编造图片中没有的内容。
- 如果某页没有文字，写作：`[本页无文字]`。
- 如果某页识别不清，保留可识别内容，并标注：`[本页部分文字不清晰]`。
- 对人物名、歌谣、规则清单等容易错的页面，汇总前再重点核对。

### 4. 生成原始故事文字

把每页文字按顺序合并成完整故事，保存到：

```text
stories/plain/<story-name>.txt
```

文件名语言要和绘本故事语言保持一致：中文绘本使用中文文件名，例如 `飞天大面包.txt`；英文绘本使用英文文件名，例如 `the-very-hungry-caterpillar.txt`。只在文件名包含 `/`、`:` 等不适合作为路径的字符时做最小替换。

原始故事文本应尽量只包含故事本身。除非用户要求，否则不要插入解释、摘要或 OCR 备注；页码可保留为简洁标题，便于用户核对。

如果输出文件已存在，先读现有文件再覆盖；如果是新文件，可以直接 `Write`。

### 5. 生成带翻页提示版本

在每一页和下一页之间插入翻页提示语，保存到：

```text
stories/with-page-turns/<story-name>.txt
```

默认格式不要包含“第几页”页码说明，因为这个版本通常用于朗读或口语播放，页码会打断故事感：

```text
[第 1 页文字]

请翻到下一页。

[第 2 页文字]
```

不要在最后一页后面添加“请翻到下一页”。原始故事文本可以保留页码用于核对；带翻页提示的口语版本不要保留页码，除非用户明确要求。

如果用户要求“更自然一点”，可以在页间使用少量变化，但保持意思清楚，例如：

- `请翻到下一页。`
- `我们翻到下一页继续看。`
- `接下来，请翻到下一页。`
- `故事还没结束，请翻到下一页。`

不要让翻页提示抢戏；它只是提醒翻页，不应该改变故事内容。

### 6. 校验输出

完成写入后做只读校验：

```bash
grep -c '^第 [0-9][0-9]* 页$' 'stories/plain/<story-name>.txt'
grep -c '请翻到下一页。' 'stories/with-page-turns/<story-name>.txt'
grep -n '\[本页\|不清晰' 'stories/plain/<story-name>.txt' 'stories/with-page-turns/<story-name>.txt' || true
git status --short
```

校验标准：

- 原始文本页码数应等于图片数。
- 翻页提示数应等于图片数减 1。
- 带翻页提示版本末尾不能再有翻页提示。
- 如果存在 `[本页无文字]` 或 `[本页部分文字不清晰]`，最终汇报中列出需复核页面。
- `git status --short` 应只出现预期新增/修改的故事文本文件；如果还修改了计划文件或 skill 文件，也要如实说明。

### 7. 汇报结果

完成后简短汇报：

- 处理了多少张图片。
- 使用了哪种排序方式。
- 原始故事文本保存路径。
- 带翻页提示版本保存路径。
- 校验结果：页数、翻页提示数量。
- 是否有识别不清或无文字页面需要用户复核。

## 输出质量原则

- 页序正确比文字润色更重要。
- 不确定就标注，不要猜测。
- 对幼儿绘本，保留简单、口语化、重复性的表达。
- 对标题页、人物页、规则页、歌谣页要特别谨慎，这些页面最容易被 OCR 错分行或错字。
- 翻页提示要像正常讲故事时的提醒，简短自然。
- 如果用户已有固定目录规范，遵循用户规范，而不是本 skill 默认结构。

## 示例

用户：

```text
帮我处理 images/小兔子 这个文件夹，按名字排序，提取文字，再生成带请翻页的版本。
```

期望行为：

1. 找到 `images/小兔子` 下的图片。
2. 按自然文件名排序。
3. 逐页 OCR；图片多时按 8–10 页一组并行只读识别。
4. 保存：
   - `stories/plain/小兔子.txt`
   - `stories/with-page-turns/小兔子.txt`
5. 带翻页提示版本不包含“第几页”页码说明，只保留故事正文和翻页提示。
6. 校验原始文本页数、翻页提示数量和 OCR 复核标记。
7. 汇报保存路径和需要复核的页面。
